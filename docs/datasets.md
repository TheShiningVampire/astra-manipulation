# Dataset and simulator choices

The initial gripper task is robomimic Lift with a Panda arm and parallel gripper. The dexterous task is Adroit Relocate: a Shadow hand attached to a six degree-of-freedom free arm. These are small, established demonstrations with executable MuJoCo environments. They are different manipulation tasks, not an embodiment-controlled comparison.

## Gripper

[Official robomimic documentation](https://robomimic.github.io/docs/datasets/robomimic_v0.1.html) recommends robosuite 1.5.1 for the converted v1.5 datasets. [Lift PH files](https://huggingface.co/datasets/robomimic/robomimic_datasets/tree/main/v1.5/lift/ph) provide 200 proficient-human demonstrations; the raw file is approximately 36.7 MB. The Hugging Face card identifies the dataset license as MIT. The raw HDF5 contains simulator states and model XML so observations can be rendered and an episode's initial conditions restored. Simulator states are used inside the environment only, never sent to the policy. The download utility returns a local SHA-256 digest for provenance; this is not an independently verified publisher checksum.

The policy receives external and wrist RGB views plus a whitelist of robot joint, end-effector, and gripper observations. Object observations are disabled. End-effector pose is robot kinematics, corresponding to pose obtained from encoders and a calibrated robot model. Commands are seven normalized OSC pose/gripper values at 20 Hz, with robosuite's standard low-level operational-space controller executing each numeric command. The adapter uses current base-frame OSC deltas; the recorded dataset metadata specifies world-frame deltas, so demonstration action replay would need frame conversion and is not implemented.

## Dexterous hand

[Minari D4RL/relocate/human-v2](https://minari.farama.org/datasets/D4RL/relocate/human-v2/) contains 25 human demonstrations and 9,942 transitions, with 30-dimensional actions. Download through `minari.load_dataset("D4RL/relocate/human-v2", download=True)`. Install `minari>=0.5.2` for the namespaced IDs. [Gymnasium-Robotics Adroit documentation](https://robotics.farama.org/envs/adroit_hand/adroit_relocate/) describes the simulator. Our pinned model uses normalized actuator controls; see the [action-space audit](action_space_audit.md) for actual gains and axes, which are more specific than the upstream position-target description. The framework uses `AdroitHandRelocate-v1`, matching the dataset environment specification. Newer upstream v2 changes reward and state-restoration behavior; do not silently mix its results with v1.

The default 39-dimensional Adroit observation contains nine privileged object/goal displacement values. The adapter discards those entries. Its corrected interface exposes the first 30 robot joint coordinates, 30 robot joint velocities, the palm's encoder-derived forward-kinematics position/orientation, and a rendered external RGB image. It excludes object velocities and all non-robot sites. Rewards and success flags stay in evaluator-only output. The visible green target is a simulator-rendered goal marker; this benchmark assumes the target is visually available. It is not an inferred hidden goal location.

The original [author's hand_dapg repository](https://github.com/aravindr93/hand_dapg) supplies the same task's 25 human demonstrations with full `init_state_dict` records. Its [official visualization script](https://github.com/aravindr93/hand_dapg/blob/master/dapg/utils/visualize_demos.py) restores those states before playback. `download_adroit_initial_states("data")` downloads the approximately 5.6 MB original file and converts initial states to `data/adroit_relocate_initial_states.json`. Passing that JSON as `--dataset-path` together with `--episode-id 0` initializes a live, rendered rollout from a recorded demonstration's initial conditions. Later observations come from the simulator evolving under model commands. The simulator retains initialization state internally; policy inputs remain only RGB and 30 robot joint coordinates.

The raw source is a pickle. The converter checks its reviewed SHA-256 before decoding and uses a restricted loader allowing only the three NumPy constructors present in that file. The runtime adapter reads plain numeric JSON, never pickle. This is a source-pinned conversion utility, not a general untrusted-pickle loader. A changed upstream artifact is rejected. The original repository is Apache-2.0 licensed; [Gymnasium-Robotics library source](https://github.com/Farama-Foundation/Gymnasium-Robotics/blob/main/LICENSE) is MIT licensed. A separate explicit license for the converted Minari demonstration files was not verified; dataset downloads remain local and are not redistributed by this repository.

The original demonstration-0 reset was validated against all 39 recorded initial observation coordinates, with maximum absolute difference `1.39e-16`. This comparison uses privileged values only in an offline environment-integrity check. All 25 recorded initial states have zero object joint translations, avoiding a known nonzero-translation restoration issue in the v1 environment. Exact subsequent historical trajectories are not guaranteed across MuJoCo versions. Minari itself omits those full initial states and remains useful for offline inspection and comparison; fresh seeded simulator resets are also supported when `--episode-id` is omitted.

An evaluator-only original action replay verifies that the simulator can complete both initial hand episodes. Episode 0 succeeds from step 183 through step 352 (170 steps); episode 1 succeeds from step 279 through step 437 (159 steps). Both end successfully. Some numerical trajectory drift exists with the newer engine, but it does not prevent these recorded controls from completing the task. Full metrics are in [replay_validation.json](replay_validation.json). Reproduce with `MUJOCO_GL=osmesa python -m astra_manipulation.replay`. This is a human-demonstration baseline, not an Astra result; demonstration actions never enter policy requests.

The tested installation uses gymnasium-robotics 1.4.2 and MuJoCo 3.3.7. Gymnasium-Robotics warns that v1 dense rewards changed after 1.2.0 without an environment-ID change. Results must identify this package version; dense rewards should not be compared to original dataset v1 rewards. Success is taken from the environment's Boolean evaluator. Remote Minari downloads require the `minari[hf]` extra.

## What the experiment can establish

Neither selected dataset provides a rich collection of natural-language instructions. Task descriptions and paraphrases in this framework are authored evaluation prompts. A task success rate demonstrates behavior on those tasks and seeds; by itself it does not establish general language understanding. Stronger evaluation needs contrasting instructions whose required actions and success predicates differ. Offline agreement with a demonstration also cannot establish closed-loop task success.

The simulator necessarily retains full state for physics and evaluation. The policy boundary, saved policy requests, and explicit observation whitelist are what enforce the no-privileged-input requirement. Robot geometry, actuator names and static limits are permissible embodiment metadata; per-step object coordinates, contacts, rewards, success flags, simulator state and demonstrations' future actions are not policy inputs.

## Recorded hand observation diagnostic

`export_adroit_samples("data/minari", "runs/adroit-dataset-samples")` exports every 50th observation of demonstration 0 (eight samples). `policy_inputs.json` contains only the 30 joint coordinates, authored instruction, and step index. Demonstration actions are stored separately in `evaluator_reference_actions.json` for offline comparison. No recorded camera frames exist in Minari, and its only per-step `info` field is `success`, so reconstructing exact RGB from those Minari records alone is unsupported. This diagnostic does not substitute for the visual closed-loop evaluation initialized from original hand_dapg states described above.
